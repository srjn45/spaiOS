## What We're Building

The full Orchestrator: structured system prompt with context injection, 10-turn conversation history, Ollama function calling with File Agent tool definitions, multi-turn conversation flow, clarifying question routing, and robust loading/error states. This is the intelligence layer that ties context capture to the UI and the file agent.

## Approach

**Session 8 — Orchestrator + function calling:**
1. `orchestrator.py`: `SYSTEM_PROMPT` template with `{app_name}`, `{window_title}`, `{visible_text}`, `{screenshot_b64}` placeholders
2. Tool definitions dict for `organize_folder`, `list_files`, `move_file`, `ask_clarification` in Ollama function-calling format
3. `ask(user_message: str) -> str`: call `context.capture()`, inject, call `ollama.chat(tools=TOOL_DEFS)`, handle tool call response → route to agent → call again for final response
4. Conversation history: `self._history: list[dict]`, append user/assistant turns, slice to last 10

**Session 9 — Multi-turn conversation:**
5. Verify `_history` is passed in each `ollama.chat` call
6. Test: "what app is open?" → answer → "what's in the file?" → AI must reference prior context
7. `reset()`: clear history on overlay close

**Session 10 — Clarifying question flow:**
8. When Ollama calls `ask_clarification`, emit `clarification_requested(question: str)` signal
9. Overlay shows question text in a distinct style (italic, different color)
10. `QLineEdit` remains active for user response; on Enter → feed answer back into `ask()` as a user turn
11. UI must visually distinguish "AI is asking" vs "AI is responding"

**Session 11 — Loading states + error handling:**
12. `QThread` worker: emit `response_ready(str)` on success, `error_occurred(str)` on exception
13. `OllamaConnectionError`: show "Could not connect to Ollama — is it running?" in overlay
14. Model-not-found: show "Model llama3.2:3b not found — run: ollama pull llama3.2:3b"
15. Long responses (>800 chars): truncate with "▼ Show more" toggle in QTextEdit
