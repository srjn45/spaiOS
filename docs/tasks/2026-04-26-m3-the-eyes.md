## What We're Building

`src/core/context.py`: the Context Capture module that assembles a structured dict of the current screen state on each user query. Three data sources: (1) a `scrot` screenshot passed to moondream for a vision description, (2) the AT-SPI accessibility tree of the focused window for visible text, (3) `xdotool` for the active window title and app name.

## Approach

**Session 6 — Screenshot + vision:**
1. `context.py`: `capture_screenshot() -> str` — `subprocess.run(["scrot", "-z", "/tmp/spai_screen.png"])`, Pillow open, base64 encode
2. `get_vision_description(screenshot_b64: str) -> str` — Ollama call to moondream with image
3. Manual test: call `get_vision_description` on a live screenshot, verify non-trivial text output
4. Wire vision description into the `capture()` return dict

**Session 7 — AT-SPI + window info:**
5. `get_window_info() -> dict` — `xdotool getactivewindow getwindowname`, parse app name from title
6. `get_atspi_text(max_chars: int = 2000) -> list[str]` — `pyatspi.Registry.getDesktop(0)`, walk focused window, collect text from `Accessible` nodes with role LABEL, EDIT, STATUS_BAR, DOCUMENT_FRAME
7. Guard: if AT-SPI raises `gi.repository.GLib.GError`, return empty list (non-accessible app)
8. Assemble `capture() -> dict` with all four fields
9. Test with VS Code open on a Python file: `visible_text` should contain code lines
10. Inject context dict into Orchestrator system prompt placeholder

## Files Touched

- `src/core/context.py` — screenshot, vision, AT-SPI, window info, `capture()`
- `src/core/orchestrator.py` — call `context.capture()` before each Ollama request, inject into system prompt

## Done When

1. `context.capture()` returns `{"app_name": str, "window_title": str, "visible_text": list[str], "screenshot_b64": str}`
2. moondream returns a description that mentions visible screen elements (not boilerplate)
3. With VS Code open on a Python file, `visible_text` contains at least one code line from the file
4. With VS Code focused, `app_name` is `"code"` or similar; `window_title` contains the filename
5. AI names the active app when asked "what app is open?" in the overlay
