# Task: AT-SPI Context Reader

**Date:** 2026-04-27
**Phase:** Phase 1 — Milestone 3
**Session goal:** Implement AT-SPI context capture that extracts app name, window title, and visible text from the focused window, then inject it as a system prompt prefix in Orchestrator.
**Notion task ID:** 34e7600e54c781da8290e0c96c87ea64

## What We're Building

A `context.py` module in `src/spaiOS/core/` that reads the active window's metadata and accessible text using `xdotool` (for window info) and `pyatspi` (for accessible text content). The orchestrator's `ask()` method is updated to prepend this context as a system prompt so the LLM knows what the user is looking at.

## Approach

1. Install system deps: `xdotool` and `python3-pyatspi` via apt
2. Add `pyatspi` to `pyproject.toml` as a system-level dependency note
3. Create `src/spaiOS/core/context.py`:
   - `get_window_info() -> dict` via `xdotool getactivewindow getwindowname`
   - `get_atspi_text(max_chars: int = 2000) -> list[str]` via pyatspi accessibility tree walk
   - `capture() -> dict` combining all fields
4. Update `Orchestrator.ask()` to call `context.capture()` and prepend system prompt
5. Leave `ask_with_vision()` unchanged (vision already provides visual context)
6. Test: open a text editor with some content, ask "what text is on screen?"

## Files Touched

- `src/spaiOS/core/context.py` — new file
- `src/spaiOS/core/orchestrator.py` — wire in context capture

## Done When

- `context.capture()` returns a dict with `app_name`, `window_title`, `visible_text`
- Asking "what text is on screen?" with a text editor open returns an answer that references actual editor content
- No crash when no accessible text is available (e.g., terminal, browser)
